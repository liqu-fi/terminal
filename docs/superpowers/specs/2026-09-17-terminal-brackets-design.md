# Скобки терминала на действии SDK — дизайн

**Дата:** 2026-09-17
**Область:** `src/features/trade/TradeForm.tsx`, `src/features/positions/{TpSlDialog,tpslPlan}.ts(x)`,
`package.json`, `e2e/support/{world,mockGateway}.ts`, `e2e/tier1/{04-trade-market,28-position-actions}.spec.ts`
**Карточка архитектурного ревью:** 17.09, №1 — «Скобки тикета: вторая, непроверенная копия правила
`tpslPlan`»
**База:** `main` @ `f7e4cc8`
**Предшественник:** SDK-часть — `monorepo` PR #783, смержена как `890270c9`, релиз `liq@0.54.0`; её
спека — `monorepo/docs/superpowers/specs/2026-09-17-position-brackets-design.md`

## Задача

Терминал считает скобки сам в двух местах. `src/features/positions/tpslPlan.ts` — план правки скобок
позиции, `src/features/trade/TradeForm.tsx:128-157` — вторая копия того же правила для скобок входа,
без единого теста и с потерянным отказом: два `submitAttached.mutate` подряд отцепляют наблюдатель от
первой мутации, поэтому отказ шлюза по TP не виден, если заполнен и SL. Ни один из путей не связывает
ноги, поэтому сработавший TP оставляет стоп жить дальше.

SDK 0.54.0 закрывает это: `bracketsPlanFor` в `@liq/core` и `useApplyBracketsMutation` в `@liq/react`
считают план, подают ноги по очереди в одной связке (`groupId`, OCO), сначала подают, потом отменяют
заменённые, а все отказы отдают одной ошибкой с именем ноги.

## Решения

1. **Оба пути — на действие SDK.** `TpSlDialog` и тикет зовут `useApplyBracketsMutation(accountId)`;
   `tpslPlan.ts` и его тест удаляются.
2. **Бамп и удаление — один коммит.** `Bracket.groupId` стало обязательным, и `tpslPlan.test.ts`
   строит скобку без него: бамп сам по себе оставляет типизацию красной.
3. **Ошибку показывает мутация.** У диалога исчезают собственные `pending`/`error` и `try/catch`:
   и то и другое даёт `useApplyBracketsMutation` (`isPending`, `error.message` вида
   `Take profit: …; Stop loss: …`). Текст в `tpsl-error` остаётся на своём месте.
4. **Тикет подаёт скобки из `onSuccess` входа**, как сейчас: скобки прикрепляются к принятому входу,
   не атомарно с ним. Отдельный наблюдатель мутации больше не нужен — действие само по себе мутация.
5. **Мёртвые ветки уходят вместе с копией правила:** `attachable` (всегда `true` при
   `TABS = ["Market","Limit"]`) и `if (tab === "Limit")` после `return` в ветке Market.
6. **Мок e2e начинает отдавать `groupId`.** Копия `GatewayOrder` в `e2e/support/world.ts` получает
   поле, фикстура условного ордера — значение, `mockGateway` переносит `groupId` из тела подачи в
   созданный ордер. Без этого `positionBrackets` в e2e видит связку `undefined`, и замена ноги
   получает новую связку вместо унаследованной — то есть проверяется не то поведение, что в проде.
7. **Вне объёма:** проверка цен TP/SL против марк-цены (`validateTakeProfit`/`validateStopLoss`);
   карточка 4 обзора (взять типы и адреса e2e-мока из SDK целиком) — здесь добавляется только
   `groupId`.

## Тесты

- Юнит-тестов на правило в терминале не остаётся — оно уехало в SDK вместе с тестами
  (`position-brackets-plan.test.ts`, `applyBracketsMutation.test.tsx`).
- `e2e/tier1/04-trade-market.spec.ts`: прикреплённые скобки проверяются на **обеих** сторонах входа
  (long и short), у ног один `groupId`, отказ шлюза по TP виден в `trade-error`, а SL всё равно подан.
  Отказ конкретной ноги ставится `page.route` внутри спеки — Playwright отдаёт приоритет маршруту,
  зарегистрированному последним, поэтому `mockGateway` не трогается.
- `e2e/tier1/28-position-actions.spec.ts`: замена ноги встаёт в связку заменяемой. Одна проверка там
  молча кодировала старый порядок — ждала подачу опросом, а отмену читала синхронно, — и с
  «подачей раньше отмены» становится гонкой: отмена начинает ждаться таким же опросом.
  Сам порядок в e2e не проверяется: он закреплён юнит-тестом SDK
  (`applyBracketsMutation.test.tsx`), а здесь потребовал бы журнала обращений в моке — лишняя
  механика ради второй проверки того же.
- Живая проверка на staging после выката: у ног входа один `groupId`, срабатывание TP снимает SL.

## Риски

- `@liqpro/liq-*@0.54.0` на момент написания в npm ещё нет (CI-джоба npm красная с 0.52.0, владелец
  публикует руками). Задача 1 не начинается, пока `npm view @liqpro/liq-core version` не покажет
  `0.54.0`.
- Шлюз не проверяет владельца связки (`liqcx/monorepo#784`). Пока проверки нет, скобки не должны
  оказаться перед пользователями: PR терминала не мержится раньше, чем закрыт #784.
